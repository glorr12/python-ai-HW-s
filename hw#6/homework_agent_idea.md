# Домашнее задание: идея AI-агента

## 1. Идея — «Test Doctor»: агент, который чинит упавшие тесты

Я пишу бэкенд на Python (Django, Flask) и автотесты на pytest. Частая рутина: тесты упали,
нужно прочитать длинный traceback, найти, где ошибка — в тесте или в коде, погуглить непонятное
сообщение и поправить. **Test Doctor** делает это за меня: запускает тесты, разбирается в причине
и предлагает конкретное исправление.

Пример запроса: *«Тесты в папке `tests/` падают, найди причину и предложи фикс»*.

## 2. Инструменты

| Инструмент | Что делает | Зачем агенту |
|---|---|---|
| `run_pytest(path)` | Запускает `pytest` и возвращает список упавших тестов и traceback | Увидеть, что именно сломано |
| `list_files(folder)` | Показывает структуру проекта | Понять, где лежат нужные модули |
| `read_file(path)` | Читает файл с кодом или тестом | Посмотреть строки из traceback |
| `web_search(query)` — Tavily | Ищет текст ошибки в интернете (документация, Stack Overflow) | Разобраться с незнакомыми ошибками и изменениями в библиотеках |
| `propose_patch(path, old, new)` | Формирует diff с исправлением, **не применяя его** | Показать фикс; применяет его человек |

Модель — Gemini через `ChatGoogleGenerativeAI`, агент — `create_react_agent` из LangGraph,
память диалога — `MemorySaver` (как в примерах урока).

## 3. Как работает (цикл ReAct: подумал → действие → наблюдение)

1. **Запуск тестов.** Агент вызывает `run_pytest` и получает, например:
   `test_create_user — KeyError: 'email'`.
2. **Поиск причины.** По traceback открывает тест и нужный модуль через `read_file`.
   Если ошибка непонятная (например, после обновления библиотеки) — ищет её через `web_search`.
3. **Вывод.** Решает, где проблема: в коде (API вернул поле `mail` вместо `email`)
   или в самом тесте (устаревшая проверка).
4. **Исправление.** Через `propose_patch` показывает diff и объясняет его в 2–3 предложениях.
5. **Проверка.** Если я применил фикс, агент снова вызывает `run_pytest` и подтверждает, что тесты зелёные.
   Если нет — повторяет цикл (максимум 3 попытки, чтобы не зациклиться).

```
Я ──запрос──► Агент (Gemini)
                 │  думает, какой инструмент нужен
                 ├──► run_pytest ──► traceback
                 ├──► read_file  ──► код теста/модуля
                 ├──► web_search ──► объяснение ошибки
                 └──► propose_patch ──► diff + объяснение ──► Я
```

## 4. Ограничения и безопасность

- Агент **не меняет файлы сам** — только предлагает diff; последнее слово за человеком.
- Работает только внутри папки проекта, не видит `.env` и секреты.
- Лимит шагов и попыток — чтобы не тратить токены впустую.

## 5. Чем полезен

Экономит время на рутинном разборе traceback, особенно в больших наборах тестов,
и объясняет причину ошибки — это ещё и помогает учиться. В будущем можно добавить
инструмент для GitHub: агент будет сам разбирать упавший CI в pull request.
